FedexShip.php : 27

Ship API: creates, validates and cancels shipments, creates and cancels tags, and retrieves the results of asynchronous shipments (ship/v1/shipments).

Creating and cancelling a shipment or a tag change real data in FedEx (a label is bought, a shipment or a pickup is voided), and a request that fails because of a timeout or a network error may have been processed anyway: a failed create(), cancel(), createTag() or cancelTag() must be checked in FedEx before it is repeated. validate() and getAsyncResults() do not change anything

create()

FedexShip.php : 273

Create a shipment (and its labels). THIS BUYS A LABEL: it is a real, billable operation.

public create(array<string|int, mixed>|stdClass $request) : stdClass

The request is checked before it is sent: the fields, their types and their allowed values are the ones of schemas/ship.json (a field that is not in the schema is an error) and the required fields must be present. What the schema cannot express (for example the fields that are required for some services, or for customs) is checked by FedEx. Fields set to null and empty lists are left out. The request is never repeated by this library, except when FedEx answers that the token is not valid, which means that nothing was processed. If an exception is thrown after the request was sent (a timeout, a network error, or a response that is not valid), the shipment may have been created: check it before trying again
