FedexConsolidationSchemas.php : 21

Definitions of the requests and responses of the Consolidation API operations that FedexConsolidation implements, generated from schemas/consolidation.json and written for SchemaValidator.

There are two sets. definitions() has all of the file, down to the last field. The file contradicts its own sample payloads in the nested objects (3 of its 19 samples pass the whole of it), so that set is only used to report problems (FedexConsolidation::checkRequest() and checkResponse()). shallowDefinitions() is the one that decides whether a request is sent: the top level of each request and response, as the file says it and as every sample of the file has it, with each nested object or list accepted as it comes

Methods

definitions()  : array<string|int, mixed>
Get the definitions of all the requests and responses, down to the last field. The names of the definitions, and of their fields, are the ones of schemas/consolidation.json, with these differences: - FullSchema-DeleteShipment is named FullSchema_DeleteShipment (the validator does not accept a hyphen in a name) - what the file writes inline or as an overlay of another definition ("this definition, but these keys are required") is a definition of its own, named after the definition and the field that contain it - RequestedConsolidationShipment requires a field called recipient, which the file never defines (the field is recipients, and it is not required there): recipient is accepted as an optional field of any type - Label.type and ShippingDocument.type have an enum of one value, the whole list of values joined in a text: they are checked as text - the items of DistributionLocations.inclusionSpecifications are the allOf of CarrierCode and ServiceCategory, which are both plain text: they are text
shallowDefinitions()  : array<string|int, mixed>
Get the definitions of the top level of all the requests and responses: the roots of ROOTS with the same fields and the same required fields, where a field that holds an object is only checked to be an object, and a field that holds a list is only checked to be a list. The values that are text, numbers or booleans, and the enums of the top level, are checked as in definitions()
