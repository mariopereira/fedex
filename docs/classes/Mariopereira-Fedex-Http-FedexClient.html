FedexClient.php : 23

JSON HTTP client for the FedEx APIs: adds the authorization headers and retries once when the token is rejected.

Optionally (see setRetryPolicy()) it also retries, with exponential backoff, the requests that are marked as safe to repeat when FedEx answers 429, 503 or 504 or when the request could not be completed, waiting at least as long as the Retry-After header asks

setRetryPolicy()

FedexClient.php : 105

Enable the retry, with exponential backoff and full jitter, of the requests that are marked as safe to repeat.

public setRetryPolicy([int $maxAttempts = 3 ][, int $baseDelayMs = 500 ][, int $maxDelayMs = 5000 ][, int $maxRetryAfterMs = 30000 ]) : FedexClient

They are retried when FedEx answers 429, 503 or 504, or when the request could not be completed (network failure, timeout, ...). The delay before the attempt n is a random value between 0 and min($maxDelayMs, $baseDelayMs * 2^(n-1)). The refresh of a rejected token (401) is separate and does not count as an attempt. When FedEx sends a valid Retry-After header with the failure, the wait is the longer of the header and the backoff delay; if the header asks for more than $maxRetryAfterMs the retries stop and the failure is thrown. Without calling this method nothing is retried

Parameters
$maxAttempts : int = 3

Total number of attempts, from 1 (no retry) to 10

$baseDelayMs : int = 500

Delay in milliseconds that the backoff starts from, 0 or more

$maxDelayMs : int = 5000

Longest delay in milliseconds, not less than $baseDelayMs

$maxRetryAfterMs : int = 30000

Longest Retry-After in milliseconds that is waited for, 0 or more. Zero ignores the header and uses only the backoff

Tags
throws
FedexClientException

When a value is out of range

Return values
