FedexPickup.php : 28

Pickup Request API: checks when a pickup is available, schedules a FedEx Express or Ground pickup, and cancels it (pickup/v1).

Checking the availability only asks FedEx, and changes nothing, so a request that failed because of a timeout, or a busy server, can be repeated (see FedexClient::setRetryPolicy()). Creating and cancelling a pickup change data in FedEx, so they are never repeated by this library, except when FedEx answers that the token is not valid, which means that nothing was processed. If an exception is thrown after one of them was sent (a timeout, a network failure), the pickup may or may not have been scheduled or cancelled: check it before sending the request again

createPickup()

FedexPickup.php : 149

Schedule a pickup. THIS ASKS FEDEX TO SEND A DRIVER: it is a real operation.

public createPickup(array<string|int, mixed>|stdClass $request) : stdClass

The request is checked before it is sent: the types and the allowed values of the fields are the ones of schemas/pickup.json (a field that is not in the schema is sent as it is, and FedEx decides about it; the types are loose, as in the examples of FedEx: a text can be a number or a boolean, a number can be a text that is a number or blank, and a boolean can be the text true or false in any case, or 0 or 1) and the required fields must be present. What the schema cannot express is checked by FedEx. Fields set to null and empty lists are left out. The request is never repeated by this library, except when FedEx answers that the token is not valid, which means that nothing was processed. If an exception is thrown after the request was sent (a timeout, a network failure), the pickup may have been scheduled: check it before sending the request again
