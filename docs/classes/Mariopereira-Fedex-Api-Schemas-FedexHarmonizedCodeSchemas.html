FedexHarmonizedCodeSchemas.php : 15

Definitions of the request and the response of the Harmonized System (HS) Code Classification API operation that FedexHarmonizedCode implements, generated from schemas/harmonized-code.json and written for SchemaValidator

Methods

definitions()  : array<string|int, mixed>
Get the definitions of the request and the response. The names of the definitions, and of their fields, are the ones of schemas/harmonized-code.json, with these differences, decided with the owner: - HsClassifyVO requires both destinationCountryCodes and originCountryCode in the file, but the documentation says that either one is required, and the minimum examples of the file send only one: both are optional, and every commodity has to have at least one of them (see hasACountry()) - the request requires at least one commodity (hsClassify, which the file does not require): the documentation requires the description and a country of a commodity - the responses have at most four subheading options and four tariff alternates in the file: the number is not checked
hasACountry()  : bool|string
Check that a commodity of the request has a destination country or an origin country (the check of each item of hsClassify)
