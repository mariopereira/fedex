Definitions of the requests and responses of the Open Ship API operations that FedexOpenShip implements, generated from schemas/open-ship.json and written for SchemaValidator.

There are two sets. definitions() has all of the file, down to the last field. The requests of FedEx's collection (schemas/collections/open-ship.json) contradict it in the nested objects of the shipments (most of them leave out requestedShipment.labelSpecification or customsClearanceDetail.commercialInvoice, which the file requires), so that set is only used to report problems (FedexOpenShip::checkRequest() and checkResponse()). shallowDefinitions() is the one that decides whether a request is sent: the top level of each request and response, as the file says it, with each nested object or list accepted as it comes

Methods

definitions()  : array<string|int, mixed>
Get the definitions of all the requests and responses, down to the last field. The names of the definitions, and of their fields, are the ones of schemas/open-ship.json, with these differences: - the ten requests (FullSchema-createOpenShipment, ...) are named with an underscore instead of the hyphen (the validator does not accept a hyphen in a name) - what the file writes inline or as an overlay of another definition ("this definition, but these keys are required") is a definition of its own, named after the definition and the field that contain it - FullSchema-RetrieveOpenShipment requires trackingId, which it never defines: it is accepted as an optional field of any type - the values of AlcoholDetail.alcoholRecipientType are LICENSEE and CONSUMER, as in schemas/ship.json (the file has CONSUMERstomer, a typo; decided with the owner)
shallowDefinitions()  : array<string|int, mixed>
Get the definitions of the top level of all the requests and responses: the roots of ROOTS with the same fields and the same required fields, where a field that holds an object is only checked to be an object, and a field that holds a list is only checked to be a list. The values that are text, numbers or booleans, and the enums of the top level, are checked as in definitions()
