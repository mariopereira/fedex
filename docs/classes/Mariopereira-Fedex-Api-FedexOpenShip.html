FedexOpenShip.php : 37

Open Ship API: creates a shipment that stays open while its packages are added, modified or deleted, over several requests, and confirms it when it is complete, which generates its labels; retrieves an open shipment or one of its packages, deletes an open shipment, and gets the results of the operations that FedEx processes asynchronously (ship/v1/openshipments).

Creating, modifying, confirming and deleting, and adding, modifying and deleting packages, change real data in FedEx. A request that fails because of a timeout or a network error may have been processed anyway: such a failure must be checked in FedEx before it is repeated, and this library never repeats those requests on its own. Only retrieveOpenShipment(), retrievePackage() and getResults() change nothing and can be repeated (see FedexClient::setRetryPolicy()).

How a request is checked. The requests of FedEx's collection (schemas/collections/open-ship.json) contradict schemas/open-ship.json in the nested objects of the shipments (most of them leave out labelSpecification or commercialInvoice, which the file requires). So a request is checked at its top level only: the required fields, the names of the fields and their types, with each nested object or list accepted as it comes, and FedEx checks the rest and answers with its errors. checkRequest() and checkResponse() check the whole of the schema and report what does not match, without stopping anything
