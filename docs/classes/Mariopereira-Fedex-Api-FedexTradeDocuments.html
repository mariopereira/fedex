Trade Documents Upload API: uploads the customs documents of an electronic trade documents (ETD) shipment, before or after it is shipped, and the images (letterhead and signature) used in the documents that FedEx generates (schemas/upload-documents.json).

This API has its own hosts (SANDBOX_URL and PRODUCTION_URL), not the ones of the other APIs; the token is the same. Three operations send the files as a multipart/form-data request, two send them encoded in Base64 in a JSON request.

Every upload stores the files in FedEx, so it is never repeated by this library, except when FedEx answers that the token is not valid, which means that nothing was processed. If an exception is thrown after it was sent (a timeout, a network failure), the files may have been stored: check it before sending them again

uploadDocument()

FedexTradeDocuments.php : 165

Upload a trade document (commercial invoice, certificate of origin, ...). THIS STORES THE DOCUMENT IN FEDEX.

public uploadDocument(array<string|int, mixed> $document, string $fileName, string $content, string $contentType) : stdClass

The description is checked before it is sent: the types and the allowed values of the fields are the ones of schemas/upload-documents.json (a field that is not in the schema is sent as it is, and FedEx decides about it; the types are loose, as in the examples of FedEx: a text can be a number or a boolean, a number can be a text that is a number or blank, and a boolean can be the text true or false in any case, or 0 or 1). Fields set to null and empty lists are left out. The request is never repeated by this library, except when FedEx answers that the token is not valid
